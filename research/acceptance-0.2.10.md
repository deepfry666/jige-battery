# 0.2.10 验收标准：任务栏直读条

背景：0.2.9 的托盘水位图标装到实机后，用户觉得还是看不清。根因是 16×16 物理像素太小，A、B、D 三套图标方案都没有解决。Claude 和反重力各出 3 个新方案，见 [design/mockups/tray-v4-compare.html](../design/mockups/tray-v4-compare.html)。用户 2026-11-20 选了**方案 4「任务栏直读条」**（反重力出的，完整稿见 [design/mockups/tray-v4-antigravity.html](../design/mockups/tray-v4-antigravity.html) 方案一），并要求**去掉低电量时的红色底框**。

方案 4：在 Windows 11 任务栏上、通知区（托盘上箭头）左边，直接横排显示每台设备的「像素设备图标 + 像素百分比数字」，字高与系统时钟一致，不用悬停就能看清。

main 上已有、尚未发布的 `66813c8`（托盘图标像素改为未预乘 alpha）一并随 0.2.10 发布。

## 硬性门槛

- G1：`dotnet build Jige.slnx -p:EnableWindowsTargeting=true` 零警告；`dotnet test Jige.slnx` 全部通过，测试数不少于现有的 386 项。
- G2：以下现有实现保持不变：`[STAThread]`；`--check`；`AddVisual(v, false, null)`；托盘 uID 由 `TrayIconPlan.StableId` 推导；悬停卡片；Fluent 右键菜单；更新页面；安装器。
- G3：只读，不新增任何设备命令。
- G4：不影响游戏：直读条只在内容变化时重画，没有定时动画，没有轮询 Explorer；全屏游戏时不显示；任何情况下都不抢焦点、不弹窗。
- G5：版本号 0.2.10（已改好）。CHANGELOG 的 `## [0.2.10]` 用用户能看懂的话补上这一项；README 同步。
- G6：不向 Explorer 注入 DLL、不 hook、不改注册表里的任务栏设置。只用公开 Win32 API 定位任务栏，并把几格自己的窗口放在任务栏上。

## T. 任务栏直读条

### 外观

- T1：每台设备一段，从左到右横排：
  - 11×11 像素设备图标（鼠标、键盘、耳机，另补一个「其他」），沿用 `tray-v4-antigravity.html` 中 `ICONS` 的像素图；
  - 充电中或已充满时，图标后面加一个 5×7 的绿色闪电（`BOLT`）；
  - 6×9 像素的加粗百分比数字和 `%`（`DIG69`）。
  - 段与段之间留 4px 间距，中间画一条 1px 的竖分隔线，颜色用设计稿的 `sep`。
- T2：**没有任何底框、底色或描边**（用户明确要求去掉低电量红底胶囊）。整条背景透明，直接融进任务栏。
- T3：颜色按现有电量状态（`Presentation.Tone`，按用户设置的阈值，不要写死 20%）：
  - 正常：图标和数字都用前景色，深色任务栏 #f0ece4，浅色任务栏 #211d19；
  - 偏低（Warning）：图标和数字用现有的警告色；
  - 过低（Low）：图标和数字一起变红，深色任务栏 #ff8080，浅色任务栏 #b42318，不加底框；
  - 充电中、已充满：数字和闪电用绿色，深色任务栏 #4ce07a，浅色任务栏 #0f7b38；
  - 休眠：保留上次读数和颜色，不变灰；
  - 读不到电量：数字位置显示 `--`，用前景色。
  - 所有颜色都是**不透明**的，不要用半透明色，避免再出现 0.2.9 那种暗色看不见的问题。
- T4：深浅色跟随任务栏（`SystemUsesLightTheme`），系统切换时立即重画。
- T5：缩放：100% 和 200% 用像素图的 1 倍和 2 倍；150% 等非整数缩放可以用最接近的整数倍像素图，也可以用 Direct2D 矢量版，但字高要接近系统时钟，看起来清晰。交付时说明你的选择。
- T6：显示哪些设备，沿用现有托盘设置：「自定义」显示已勾选的活跃设备；「只显示电量最低的一台」只显示一段。已断开的设备不显示。顺序与面板一致。

### 位置与窗口

- T7：位置放在主显示器任务栏上、通知区（托盘上箭头）的左边，垂直居中。用公开 API 找 `Shell_TrayWnd` 及其中通知区的位置，具体方案自行调研。可以参考 TrafficMonitor 在 Windows 11 上的做法，只学思路，不要复制 GPL 代码。窗口形式（挂成子窗口，还是放一个以任务栏为 owner 的置顶分层窗口）也自行选择，交付时说明选择和理由。要求：
  - 不遮挡任务栏上的应用按钮。左对齐任务栏上应用很多、放不下时，不显示直读条，自动退回托盘图标；
  - 任务栏获得焦点、点开开始菜单或通知中心后，直读条仍要正确叠在任务栏上，不能被盖住或跑到别的窗口上面；
  - 任务栏设为自动隐藏时，跟着任务栏一起隐藏和出现；
  - 任务栏不在屏幕底部时（Windows 11 默认不支持，但可能有第三方工具改过），退回托盘图标；
  - Explorer 重启（`TaskbarCreated`）、分辨率或 DPI 变化、任务栏大小变化后，自动重新定位；
  - 全屏应用或游戏在前台时隐藏，退出后恢复。可以复用现有的游戏判定。
- T8：交互：
  - 左键单击直读条，和单击托盘图标一样打开面板；
  - 右键打开现有的 Fluent 右键菜单；
  - 悬停显示现有的悬停卡片，内容同「只显示电量最低的一台」模式的列表；
  - 鼠标在直读条上时，不能影响任务栏原有的右键菜单或拖拽之外的其他区域。
- T9：托盘图标：直读条显示期间，托盘只保留一个「几格」默认图标，用来点开面板，也作为 Explorer 异常时的入口；设备托盘图标不再显示。退回托盘图标模式时，恢复 0.2.9 的水位图标（已含 alpha 修复）。

### 设置与回退

- T10：设置页新增「显示位置」：
  - 「任务栏（推荐）」：默认值，老用户升级后也默认这个；
  - 「托盘图标」：即 0.2.9 的水位图标。
  - 切换立即生效，不需要重启几格。
- T11：自动回退：选了「任务栏」，但找不到任务栏或通知区、放不下、或任务栏不在底部时，自动改用托盘图标显示。这只是临时回退，不改写用户的设置；条件恢复后自动回到直读条。日志记录回退原因（只记原因类别，不记窗口标题或进程名）；诊断报告的设置摘要旁边写明当前实际的显示位置和原因。

### 测试

- T12：单元测试覆盖：
  - 直读条布局：1、2、3 台设备时的总宽度；每段的图标、闪电、数字位置；分隔线位置；`100%`、`--`、个位数的宽度；
  - 颜色：各种状态选对颜色，没有任何底框像素，所有像素都不透明；
  - 位置计算：给定任务栏矩形、通知区矩形、应用按钮占用范围和 DPI，算出直读条位置，或者判定放不下；
  - 回退判定：各种回退条件下得出正确的实际显示位置，并且不改写设置；
  - 设置迁移：旧配置升级后默认用「任务栏」。
- T13：给 `TrayIconPreview` 补上直读条导出，交付时附 100% 和 200%、深浅两种任务栏的 PNG。
