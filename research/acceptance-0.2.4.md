## L. 罗技

### L1 接收器完全通用

- 已知接收器列表按 Solaar 补全：Unifying、Nano、Lightspeed、Bolt 各型号。来源写进 `docs/protocols.md`。
- 产品名含 "receiver"、"dongle" 或「接收器」的 `046D` 长报告集合，不在列表里也按同样流程**完整读取**槽 1–6。现在的"未知 PID 只探测一次 Root"限制要去掉。
- 第一条只发 Ping，回复格式不符合 HID++ 就按 0.2.2 的安全门 ③ 拦截并记住。

### L2 老款 HID++ 1.0 设备

- Ping 返回错误码 `0x01`（invalid sub id）时，说明设备是 HID++ 1.0。这时改读寄存器 `0x0D`（百分比加状态）和 `0x07`（档位加充电字节）。
- 解析规则参照 HaloBattery 的说明：`0x07` 的档位 7、5、3、1 分别换算成约 100%、50%、20%、5%，界面显示为估算值 `≈`。
- 只在没有任何 2.0 功能回复时才读寄存器。

### L3 线缆直连

- 罗技无线鼠标或键盘插上 USB 线时，设备自身 PID 下有 `FF00:0001`、`FF00:0002` 两个集合，按设备编号 `0xFF` 读取。
- 能正确显示充电中。同一台设备同时出现在接收器和线缆上时只显示一份，优先线缆的读数。

### L4 蓝牙

两条路线同时做：

- **HID++ over BLE**：蓝牙 HID 设备的 VID 为 `046D`，经典蓝牙路径形如 `VID&0002046D`，BLE 路径形如 `_Dev_VID&02046D_PID&…`，带 `FF43:0202` 长报告集合时，按设备编号 `0xFF` 走功能发现读电量。
- **Windows 蓝牙电量属性**（适用于所有品牌）：读取设备属性 `{104EA319-6EE2-4701-BD47-8DDBF425BBE5}, 2`，也就是「设置 → 蓝牙和设备」里显示的电量。这条路线不对设备发任何命令。依据是 BatteryHub `generic.cpp` 的做法（GPL，只参考思路）。
- 同一台物理设备两条路线都读到时只显示一份，优先 HID++（它能给出充电状态）。去重依据 Container ID 或蓝牙地址，只在内存里比较，不写进日志或报告。
- 设置页新增开关「显示蓝牙设备」，默认开启。
- 蓝牙设备显示为「蓝牙」连接方式，在线、休眠、断开的判断遵守 0.2.3 的 R 节：Windows 报告已断开才算离线，没有新读数算休眠。

### L5 耳机

- 用 HID++ 2.0 的罗技无线耳机（G533、G535、G733、G935、G PRO X Wireless 等），长报告集合多为 `FF43:0202`，G535 在 `000C:0001`，以 HeadsetControl 和 HaloBattery 为准。
- 按设备编号 `0xFF` 读取，优先 `0x1004`，其次 `0x1F20`（ADC 毫伏，标志位 bit0 表示已连接，bit1 表示充电）。毫伏换算成百分比时标注估算。
- Centurion 系列（G PRO X 2 等）保持现状；PRO X 3（`0B45`）继续禁用。

### L6 缓存与效率（backlog C #11）

- 功能索引按"接收器 + 槽位 + Unit ID 摘要"缓存在内存里，同一个设备从第二轮起只发电量读取一条命令。
- 收到断开、重连推送，或者接收器被拔出时，清掉对应缓存。
- 错误回复可能以短报告（`10 xx 8F`）出现在短集合上。有短集合时同时监听它，不再在长报告句柄上空等，避免每个空槽都等满超时。
- 测试要证明：第二轮查询不再发 Root 查表；空槽错误回复能立即收到。

### L7 电量推送

监听现有推送通道时，顺便解析设备主动推送的电量变化事件（`0x1004`、`0x1000` 的事件通知），收到就直接更新读数，不额外发命令。

### L8 在线语义（与 0.2.3 的 R 节一致）

- 接收器 Ping 返回 HID++ 1.0 错误报告 `8F`，错误码为 `0x09` 或 `0x04`（已配对，但关机或不在范围内），或者收到断开推送 → 离线。HID++ 2.0 的 `FF` 错误报告使用不同的错误码表。
- Ping 没有任何回复 → 休眠，保留读数，图标不变灰。
- 有测试。

### L9 诊断

诊断报告的每台罗技设备写明：

- 连接路线：接收器槽位 N、线缆、蓝牙 HID++、蓝牙属性；
- HID++ 版本；
- 找到的功能及索引；
- 实际用了哪个电量功能、原始回复的摘要；
- 走蓝牙属性的设备注明"由 Windows 提供"。

Unit ID 和蓝牙地址不得以原文出现，有测试。

## 实机反馈修复（2026-11-20，公司电脑）

用户在公司电脑上试用后发现几个问题。现场证据：

- 装的其实是 **0.2.2**，不是 0.2.4 测试版。
- MX Anywhere 3S（槽 2）和 MX Keys S（槽 1）都是经 Bolt 接收器 `046D:C548` 读到的，不是蓝牙。
- 日志里鼠标和键盘交替"在线 ↔ 离线"：0.2.2 把没有回复的休眠设备当成了离线。0.2.3 的 R 节已经修了这个问题。
- `state.json` 里同一个接收器、同一个槽位存了两套 ID：0.2.2 读配对记录生成的 `…/1/wpid-B378`、`…/2/wpid-B037`，从来没有读数；另外还有真正有读数的 `…/unit-…`。这两套 wpid ID 就是面板上的「Logitech 无线设备（槽 1）」「槽 2」。

需要在 0.2.4 里修复的问题如下，版本号不变，因为 0.2.4 还没发布。

- F1：**从来没读到过电量的条目不显示。**
  - 槽位回复「不可达」（`0x09` / `0x04`），而且本次运行中这个槽位从来没出现过已知设备时，适配器不输出任何读数，不能再生成「Logitech 无线设备（槽 N）」这种条目。
  - 读取 `state.json` 时迁移旧数据：删掉从来没有读数（`lastOnline` 为空，最近读数也为空）的设备，包括 0.2.2 留下的 `wpid-*` 条目，同时清理对应的配置项。
  - 要有测试。
- F2：**几格重启后，休眠的接收器设备保持原来的身份。** 重启后，设备在休眠中不回复时，按 0.2.4 现有逻辑，接收器还在就算休眠，要继续沿用 `state.json` 里这个槽位最近一台设备的名称和读数，不得显示为离线或新条目。用模拟数据测"重启 → 首轮不回复 → 显示休眠中的 MX Anywhere 3S"。
- F3：**查询间隔选项和保存的值不一致。** 配置里的 `PollSeconds` 不在选项（30 秒 / 1 分钟 / 2 分钟）里时，读配置时取最接近的选项并保存，例如 15 秒改成 30 秒。界面显示的值必须能在选项里找到对应项。要有测试。
- F4：**托盘显示改成自定义。** 设置页「托盘显示」展开后有两个选项：
  - 「只显示电量最低的一台」；
  - 「自定义」。选中后，下面直接列出所有已知设备，每台一个勾选框，勾上的设备各占一个托盘图标。

  这些勾选框和设备页里的勾选是同一份设置，两边同步。旧配置里的「每台设备一个图标」视为「自定义」。设计原型 `design/ui-claude.html` 同步更新。
- F5：**托盘不显示断开的设备。** 用户问"不连接的设备有必要显示吗"，结论是不显示。
  - 托盘悬停提示只列活跃设备，即在线或休眠中的设备；
  - 自定义模式下，离线设备的图标先移除，重新连上后用同一个 uID 加回来，Windows 仍能记住它在时钟旁的位置；
  - 一台活跃设备都没有时，保留单个「几格」图标；
  - 面板底部的「离线设备（N）」折叠区保留，用来移除不再使用的设备。

  这一项替代 0.2.2 的 B6「离线图标变灰保留」，CHANGELOG 里要写清楚。
